# Monorepo Pre-Migration Audit Report

## 1. Executive Summary
This document provides a comprehensive audit of the existing repository state at `d:\Izi\base-source`. The goal is to evaluate the current architecture, identify gaps, and outline a migration plan to reach the target 4-app Monorepo Architecture (`backend`, `mobile`, `admin`, `web`) with well-defined shared packages, robust CI/CD, and AI-friendly documentation.

## 2. Current Architecture
The repository is currently structured as a pnpm workspace with TurboRepo, featuring the following main components:
- **`apps/backend`**: A NestJS + Prisma backend serving APIs.
- **`apps/web-admin`**: A Next.js (App Router) frontend functioning as an admin panel.
- **`apps/mobile`**: A native Android (Kotlin + Jetpack Compose) application, split into `:core` and `:app` modules. It is correctly excluded from the pnpm workspace and uses Gradle.
- **`packages/api-contract`**: Contains OpenAPI specifications generated by the backend and TypeScript types generated via `openapi-typescript`.
- **`packages/shared-ts`**: Contains shared utilities (currently minimal).
- **`scripts/`**: Contains deployment scripts (`deploy.sh`).
- **`ai_prompts/`**: Contains legacy AI prompt files (`00.deploy.md`, `01.list tasks project.md`).

## 3. Architecture Gaps & Missing Components
- **Missing Applications**:
  - `apps/web` is entirely missing. The target architecture requires a clear separation between `admin` (internal dashboard) and `web` (public-facing application).
- **Misnamed Applications**:
  - `apps/web-admin` should be renamed to `apps/admin`.
- **Missing Packages**:
  - `packages/config` (for shared ESLint, Prettier, TypeScript configs) is missing.
  - `packages/ui` (for shared UI components) is missing.
- **Missing Tooling**:
  - Git hooks (Husky, lint-staged) and commit conventions (commitlint) are not explicitly configured.
  - Changesets are missing for versioning and changelog generation.

## 4. Problems Identified

### 4.1 Dependency & Structure Problems
- The backend API contract generation flow is currently internal to `apps/backend` and outputs directly to `packages/api-contract`. While functional, the process needs standardization to ensure clear boundaries.
- The `tsconfig.base.json`, `.eslintrc`, and `.prettierrc` setups across apps are duplicated and not centralized via a `packages/config` package.
- `apps/web-admin` has tightly coupled API calls using `axios` and `api-contract.ts` that could be better structured using a centralized SDK approach if appropriate, or properly typed using the `api-contract` package.

### 4.2 Security Problems
- **Hardcoded Secrets**: Found hardcoded dummy/real passwords and JWT fallback secrets in several locations:
  - `ai_prompts/00.deploy.md`
  - `.env.example`
  - `docker-compose.yml`
  - `apps/backend/prisma/seed.ts` (passwords).
  - `apps/backend/src/config/app-config.service.ts` defaults `JWT_SECRET` to `your-secret-key` if the env variable is missing, which is a security risk in production.

### 4.3 Build & Testing Gaps
- `pnpm lint` currently fails out-of-the-box, indicating linting errors in the existing codebase that need to be resolved.
- Testing infrastructure is present but coverage is likely incomplete. `apps/backend/test/` exists, and Android tests pass, but `apps/web-admin` lacks comprehensive testing setup.
- CI/CD workflows (`.github/workflows/`) are missing or incomplete for a monorepo setup.

### 4.4 Documentation & AI Workflow Gaps
- The current `ai_prompts/` folder contains ad-hoc, legacy markdown files rather than a structured AI Engineering Knowledge Base.
- Missing core documentation such as `AGENTS.md`, `PROJECT_CONTEXT.md`, `ARCHITECTURE.md`, `CODING_RULES.md`, etc.
- No established `.github/ISSUE_TEMPLATE/` or PR templates.
- Architecture and decision records (`docs/architecture`, `docs/decisions`) are mostly absent.

## 5. Recommended Architecture
The target architecture will follow a strict Monorepo 4 Application + Shared Packages Architecture:
```text
/
├── apps/
│   ├── backend/
│   ├── mobile/
│   ├── admin/
│   └── web/
├── packages/
│   ├── api-contract/
│   ├── shared-ts/
│   ├── config/
│   └── ui/
├── ai_prompts/
├── docs/
├── scripts/
├── .github/
└── ...
```
All dependencies will strictly flow downwards (`apps -> packages -> external`). Apps will only communicate via APIs or shared packages.

## 6. Migration Plan

### Phase 1: Preparation & Security Remediation (Immediate)
- Fix all security issues: Remove hardcoded secrets from configs, seeds, and codebases. Ensure `AppConfigService` throws an error if `JWT_SECRET` is missing in production.
- Reorganize root directories (create `docs/`, structure `.github/`).

### Phase 2: AI Engineering Knowledge Base Setup
- Overhaul `ai_prompts/` to contain structured markdown files (`AGENTS.md`, `PROJECT_CONTEXT.md`, etc.).
- Delete legacy prompt files.

### Phase 3: Packages Standardization
- Create `packages/config` and migrate ESLint, Prettier, and TypeScript base configs there.
- Create `packages/ui` as a shared UI component library.
- Refine `packages/shared-ts` and `packages/api-contract`.
- Update all apps to use `packages/config`.

### Phase 4: Apps Reorganization
- Rename `apps/web-admin` to `apps/admin`.
- Create `apps/web` as a fresh Next.js App Router application.
- Verify `apps/backend` structure against standard NestJS domain-driven design.
- Verify `apps/mobile` Gradle configuration and integration with the root project.

### Phase 5: CI/CD & Tooling
- Setup Husky, lint-staged, and commitlint.
- Ensure all TurboRepo commands (`build`, `lint`, `typecheck`, `test`, `dev`) work flawlessly from the root.
- Add application-specific dev commands (`pnpm dev:backend`, `pnpm dev:admin`, etc.) in root `package.json`.
- Fix existing linting errors.

### Phase 6: Final Audit & Validation
- Run all build, test, and lint commands.
- Verify dependency graph.
- Document the final architecture in `docs/architecture/MONOREPO_ARCHITECTURE.md`.
